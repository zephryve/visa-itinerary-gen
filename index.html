visa-itinerary-gen

签证行程计划书生成器
FlyAI Hackathon 2026-03 zephryve@gmail.com github.com/zephryve
快速概览

一份行程单值多少钱？30-110 元。这个 Skill 让它免费。

用户问题：申根签证的行程计划书需要真实的航班、酒店、景点信息按领馆格式编排，普通用户要么花 3-5 小时自己查+排版，要么花 20-130 元找淘宝代做或买携程加价档——而这些代做服务本质上也只是人工查询 OTA 的供给再排版。

把签证行程计划书这个"有人愿意花钱找人代做"的刚需环节，用 AI 直接串联飞猪自有的机票、酒店、景点供给，30秒生成基于真实供给的领馆级行程单，省下 30-110 元代做费，又让每一项查询结果都是飞猪的可预订商品。

用 AI 把"签证材料准备"这个刚需场景变成飞猪的跨品类订单入口
——行程单即购物车。
#问题回答
1用户卡在哪？行程计划书是签证材料中唯一需要从零创作的文档，3-5 小时手工查+排版。
2帮他做什么？用户说一句话，30秒生成领馆级行程表 + 飞猪预订链接。
3输入/输出？输入：一句话说清目的地+日期+人数（如"4人4月底从杭州去意大利法国，5月4号回"）。输出：① 行程表 PDF（纯英文，单页 A4）② 预订链接 HTML（中英各一份，含推荐理由+复制按钮）。
4失败怎么办？flyai 查不到时标注"需人工确认"，保证 80%+ 完整度。
差异化

为什么这不是"又一个行程规划"

ClawHub 上已有 tour-planner、travel-itinerary-planner 等行程规划 Skill，它们输出"旅游攻略"——给自己看的。这个 Skill 输出"签证行程计划书"——给签证官看的。

普通行程规划 Skill

  • 给自己看，"玩得开心"
  • 中文或英文均可
  • 可以写"自由活动"
  • LLM 可以虚构数据
  • 无签证专属字段

visa-itinerary-gen

  • 给签证官看，"证明你会按时回来"
  • 必须全英文
  • 每天必须填满具体景点+酒店+交通
  • flyai 真实 API 数据，不编造
  • 主申请国判断 + 申根天数校验
竞品空白：ClawHub/OpenClaw 生态内没有任何签证文书类 Skill。
90%+ 准确率：flyai 提供真实数据，LLM 只做排版——数据是真的，LLM 不编。
产品价值

一份行程单值多少钱？

用户价值佐证

付费需求真实存在——行程单代做是一个有真实交易的市场：

某OTA · 代做省¥110社交平台 · 已售300+二手平台 · ¥30-100
自备机酒材料 ¥418 vs 代做行程材料 ¥528，差价 ¥110 搜索行程单，4 个商品合计 628 单，单价 ¥4-50 一对一定制 ¥30 起，专业卖家行程单单项 ¥100
结论：一份行程单的市场价值在 ¥30-110 之间。¥30 = 闲鱼人工定制起步价，¥110 = 携程有无机酒材料的官方差价。付费需求真实存在，本 Skill 将其免费化。

用户三重价值

省钱：免费替代 ¥30-110 的付费服务。省时：3-5h → 30s。提高通过率：真实数据比随便写更可信。

"可能还是因为我行程做的不够用心吧，没有具体游玩的项目"——结果只拿到了1个月签证
来源：小红书 · 爱丁堡法签
"行程单应反映申请人的实际出行计划——不应该是旅行社出具的模板行程单。使馆可能会致电问询行程细节。"
来源：VFS Global · 丹麦签证材料指南

对飞猪平台的价值

每份行程单 = 一个飞猪订单转化入口。酒店和航班全部附飞猪预订链接，用户下一步就是预订。

酒店推荐策略：三级优先级

签证场景对酒店的特殊要求：必须可退（拒签 = 不可退酒店预订纯亏损）。

优先级策略说明
P0飞猪比价优势酒店按城市预制含税价优于 Trip.com / Booking 的可退酒店，平台增长核心抓手
P1支持免费退改的酒店签证场景刚需。当前 flyai 不支持，首版文书提示用户选可退酒店
P2flyai 常规搜索结果兜底，标注"请确认退改政策后再预订"

技术实现

flyai 调用链路

用户输入 → 参数解析（目的地 / 日期 / 人数） ↓ 并行调用 flyai ┌───────────┼───────────┐ search-flight search-hotels search-poi └───────────┼───────────┘ ↓ 数据聚合 ↓ 内置逻辑（申根天数校验 + 主申请国判断） ↓ 输出生成 ┌───────────┴───────────┐ 行程表 PDF 预订链接 HTML （纯英文 A4） （中文版 + 英文版）
调用用途关键约束
search-flight国际航班 + 城际交通—
search-hotels每城 1-2 家酒店必须带日期 小城市需校验地址
search-poi每城 TOP 景点必须用中文城市名
产品反馈

flyai 能力缺口

Agentic Coding 中发现的 6 个能力缺口，建议反馈给 flyai 团队：

#缺口影响建议
1search-hotels 不支持"免费取消"筛选签证场景需可退酒店增加退改政策参数
2search-hotels 海外不带日期返回空开发者踩坑文档标注必填
3search-flight 不返回退改规则退改翻译器无法实现增加票价规则字段
4fliggy-fast-search"免费取消"语义未生效关键词无实际筛选优化语义理解
5search-poi 不支持英文城市名"Milan"返回空支持英文查询
6search-hotels 小城市名歧义"Nice"返回泰国酒店结合地理位置过滤
异常处理

当 flyai 查不到数据时

场景处理方式
航班查不到标注"需人工确认"，给出备选交通（火车）
酒店无结果标注"需人工选择"，不阻塞文书生成
申根停留超 90 天文书顶部显著预警

技术依赖

输出格式与安装

行程表 PDF

依赖 playwright + Chromium。HTML 模板（Times New Roman，A4 竖版）→ playwright 渲染 PDF → 删除中间 HTML。

pip install playwright && python -m playwright install chromium

预订链接 HTML

无额外依赖。HTML 内嵌 CSS + JS，单文件可独立运行。字体 Georgia + Playfair Display（Google Fonts），跨 Mac / Windows 兼容。模板位于 skill-package/templates/。
